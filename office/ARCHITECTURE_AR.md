# خطة المكتب الافتراضي — العربية

## الوضع الحالي

- واجهة أولية في `office/index.html` على فرع `virtual-office-foundation`.
- الواجهة الحالية تعرض بيانات تجريبية فقط؛ لم تتصل بقاعدة بيانات المؤسسة.
- لم تُعدّل ملفات التشغيل في `main`، ولم يتغير مسار Telegram.
- نواة المؤسسة الحالية موجودة في `orgx.py`، ومحرك تشغيل الوكلاء في `agent_run.py`، وواجهة Telegram في `org_bot.py`.

## حقيقة مهمة عن الاستضافة الحالية

ملف `.github/workflows/org.yml` يشغّل الشركة داخل GitHub Actions على دورات:
1. استعادة قاعدة البيانات من الحالة المشفرة.
2. تشغيل `org_bot.py cloud 270` لمدة محدودة.
3. حفظ الحالة المشفرة.
4. إنهاء المهمة ثم إطلاق دورة لاحقة.

هذا ليس خادماً دائماً، ولا يوفر واجهة API مستمرة أو اتصال WebSocket. كما أن GitHub Pages يستضيف ملفات الواجهة الثابتة فقط ولا يشغّل Python أو يوفّر قاعدة بيانات خلفية.

## قواعد الأمان

- لا تُنشر `organization.db` أو نسخة منها أو محتوياتها أو سجل الرسائل والذاكرة في مستودع عام أو GitHub Pages.
- لا توضع مفاتيح Telegram أو مفاتيح النماذج أو `STATE_PASS` داخل JavaScript أو HTML أو ملفات عامة.
- لا تُعرض أدوات Shell أو Python أو GitHub أو HTTP أو النشر الخارجي كأزرار مباشرة في الواجهة.
- كل عملية ذات أثر خارجي، وتوظيف وكيل، وتغيير هيكل المؤسسة، واعتماد نتيجة، تحتاج تحقق صلاحية وموافقة صريحة.
- تبقى Telegram قناة تشغيل قائمة إلى أن يثبت تكافؤ الواجهة الجديدة ويوافق المالك على الانتقال.

## مراحل التنفيذ

### المرحلة 1 — واجهة العرض
- استكمال واجهة عربية متجاوبة.
- فصل بيانات العرض التجريبي بوضوح عن بيانات النظام الحقيقية.
- إضافة شاشات الموظفين والأقسام والمهام والتشغيلات والموافقات والتقارير.

### المرحلة 2 — عقد API للقراءة فقط
- تحديد حقول JSON محددة من جداول المؤسسة.
- عرض الموظفين والأقسام والمهام والموافقات والتشغيلات وسجل النشاط.
- عدم كشف التفكير الداخلي أو محتوى الأسرار أو كامل سجل الأدوات.
- اختبار الاستعلامات على نسخة اختبارية من قاعدة البيانات، لا على بيانات الإنتاج.

### المرحلة 3 — جسر اتصال آمن
- اختيار وسيط خلفي مجاني فعلاً بعد التحقق من حدود الاستضافة والخصوصية والاستمرارية.
- المصادقة والتحقق من صلاحية كل طلب، وتقييد CORS، والتحقق من المدخلات، وسجل تدقيق.
- لا يُعتمد نشر لقطات حالة المؤسسة على مستودع عام.
- إن لم يتوفر وسيط مستضاف آمن ومجاني، يكون البديل تشغيل الجسر محلياً على جهاز المالك مع بيان أثر بقاء الهاتف والعملية قيد التشغيل.

### المرحلة 4 — إجراءات التحكم
- البدء بإجراءات محدودة: إنشاء مهمة، إسنادها، وقراءة تفاصيلها.
- بعد ذلك الموافقات ومراجعة النتائج وإدارة الموظفين والأقسام.
- فصل القراءة عن التعديل، وإظهار تأكيد واضح قبل أي إجراء مؤثر.

### المرحلة 5 — الانتقال
- اختبار الواجهة والجسر على نسخة معزولة.
- مقارنة النتائج مع Telegram.
- لا يُوقف Telegram ولا يتغير مسار الإنتاج إلا بعد موافقة المالك.

## معيار القبول

لا توصف الواجهة بأنها متصلة أو حية إلا بعد أن تأتي حالة الموظف والمهمة من قاعدة البيانات الفعلية عبر جسر موثّق، مع اختبار انقطاع الاتصال والصلاحيات. ولا توصف بأنها بديل Telegram إلا بعد تنفيذ الوظائف الأساسية واختبارها عملياً.
