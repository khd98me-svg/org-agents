# تشغيل جسر المكتب الافتراضي

## ما أُضيف

`server.py` خادم Python صغير يعتمد على المكتبات القياسية فقط. يقرأ قاعدة SQLite بوضع القراءة فقط ويعرض:

- `GET /api/health`
- `GET /api/snapshot`: الموظفون، الإدارات، المهام، الموافقات المعلقة، وآخر التشغيلات.

كل مسارات API تتطلب ترويسة:
`Authorization: Bearer <OFFICE_TOKEN>`

طلبات POST وPUT وDELETE مرفوضة دائمًا. لا يعيد الخادم محتوى الموافقات أو نتائج المهام أو الذاكرة أو سجل التفكير أو الأسرار.

## تشغيل محلي تجريبي

من مجلد المشروع، بعد توفر نسخة قاعدة بيانات محلية موثوقة:

```bash
export OFFICE_DB="$PWD/organization.db"
export OFFICE_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
python office/server.py
```

افتح `http://127.0.0.1:8765/` من المتصفح على الجهاز نفسه. احتفظ بالرمز في بيئة التشغيل فقط، ولا تضعه في HTML أو JavaScript أو GitHub.

الخادم يرتبط بـ `127.0.0.1` افتراضيًا. لا تغيّر `OFFICE_HOST` إلى `0.0.0.0` ولا تعرض المنفذ للإنترنت.

## قيد الربط مع الشركة الحالية

قاعدة الإنتاج الحالية تُستعاد داخل مشغّل GitHub Actions من الحالة المشفرة، ثم تُحفظ مجددًا عند انتهاء الدورة. هذا الخادم لا يستطيع قراءة قاعدة Actions عن بُعد، ووجوده في المستودع لا يجعله خدمة مستمرة. كما أن GitHub Pages لا يشغّل Python.

لذلك لا تعتبر الواجهة متصلة ببيانات الإنتاج بعد. يلزم أولًا اختيار مكان تشغيل موثوق للجسر وإتاحة نسخة قاعدة بيانات له بطريقة خاصة وآمنة. لا تنشر قاعدة البيانات أو نسخة غير مشفرة منها في المستودع أو Pages أو artifacts عامة.

## فحوص ما قبل الاعتماد

- اختبار القراءة على نسخة اختبارية من قاعدة البيانات.
- التحقق من أن API لا يكتب إلى SQLite.
- التحقق من رفض الطلبات بلا رمز أو برمز خاطئ.
- اختبار عدم كشف النتائج أو نصوص الموافقات والذاكرة.
- مراجعة مزامنة الحالة من GitHub Actions قبل أي ربط بالإنتاج.
- إبقاء Telegram ومسار Actions الحاليين دون تغيير حتى اجتياز الاختبارات وموافقة المالك.
